# Practice Design

How to design stage-appropriate exercises that build real understanding, not just familiarity.

## Design Principles

1. Every exercise must have a clear "done" standard the learner can self-assess against
2. Exercises should produce an artifact (a map, an explanation, an analysis, a design)
3. Difficulty should increase along specific dimensions, not just "harder"
4. Each exercise should reveal whether the learner actually understood or just memorized

## Exercise Taxonomy

### Type 1: Concept Mapping
**Purpose**: Test whether the learner sees relationships, not just terms

Examples:
- Draw the relationship between concepts A, B, C, D
- Identify which concepts are instances of a broader category
- Find the concept that doesn't belong and explain why
- Predict what would happen if concept X were removed from the system

**Pass criteria**: The map shows non-obvious connections and correct hierarchies

### Type 2: Explanation Tasks
**Purpose**: Test whether the learner can reconstruct reasoning, not just repeat conclusions

Examples:
- Explain why method X works for problem Y (mechanism, not just "it does")
- Explain to a specific audience (a manager, a student, a skeptic)
- Explain what would break if assumption Z were violated
- Explain the difference between two commonly confused things

**Pass criteria**: The explanation is correct, uses appropriate level of detail, and addresses the "why"

### Type 3: Analysis Tasks
**Purpose**: Test whether the learner can apply frameworks to new cases

Examples:
- Read this paper/doc/project and identify: method, assumptions, metrics, limitations
- Given this system, identify the failure modes
- Compare two approaches on specific dimensions
- Find the weakest assumption in this argument

**Pass criteria**: Analysis is structured, identifies non-obvious points, and is defensible

### Type 4: Design Tasks
**Purpose**: Test whether the learner can make and justify decisions

Examples:
- Design a solution for problem X with constraints Y
- Given three approaches, choose one and justify with tradeoffs
- Propose an experiment to test claim Z
- Design an evaluation for system W

**Pass criteria**: Design addresses constraints, tradeoffs are explicit, risks are identified

### Type 5: Judgment Tasks
**Purpose**: Test whether the learner can evaluate quality like an expert

Examples:
- Rate this resource: is it suitable for a beginner? Why or why not?
- Is this claim well-supported? What evidence would change your mind?
- Is this implementation good? What would you change?
- Is this research question worth pursuing? What's the expected value?

**Pass criteria**: Judgment is calibrated, reasoning is explicit, edge cases are considered

## Stage Progression

### Entry Stage (1-hour level)
- Concept mapping: identify and connect 5-8 core concepts
- Explanation: explain the topic in 3 sentences to a smart non-expert
- Judgment: given 3 resources, rank them by usefulness for a beginner

### Basic Stage (1-day level)
- Explanation: explain a typical case end-to-end
- Analysis: read one key resource and extract its main claims and evidence
- Judgment: identify one common misconception and explain why it's wrong

### Intermediate Stage (1-week level)
- Analysis: compare two approaches on 4+ dimensions
- Design: propose a small project and justify choices
- Judgment: evaluate a real system/paper and identify strengths and weaknesses

### Advanced Stage (1-month level)
- Design: create a complete plan (project/research/decision framework)
- Judgment: evaluate others' work with expert-level criteria
- Synthesis: identify a gap or opportunity that isn't obvious from existing materials

## Feedback Mechanisms

For each exercise, specify how the learner can check their work:

| Mechanism | When to use |
|-----------|-------------|
| Compare to reference answer | Factual/structural exercises |
| Self-check questions | "Can you explain WHY each connection exists?" |
| Peer review criteria | Design and judgment tasks |
| Empirical test | "Run it and see if it works" (technical topics) |
| Expert comparison | "Here's how an expert would approach this" (after attempt) |

## Common Pitfalls in Practice Design

- **Too easy**: Exercises that can be completed by copying from the materials
- **Too vague**: "Think about X" without a concrete deliverable
- **No feedback path**: Exercises where the learner can't tell if they got it right
- **All recall**: Exercises that test memory rather than understanding
- **Skipping stages**: Jumping to design tasks before concepts are solid
