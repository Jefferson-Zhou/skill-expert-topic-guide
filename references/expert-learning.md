# Expert Learning

How experts learn differently from novices, and how to replicate expert learning strategies in guided instruction.

## Expert-Novice Differences

The core insight from cognitive science: experts and novices don't just know different amounts — they organize knowledge differently.

| Dimension | Novice | Expert |
|-----------|--------|--------|
| Organization | By surface features (keywords, names) | By deep structure (principles, mechanisms, constraints) |
| Problem approach | Pattern-match to examples seen before | Classify by underlying type, then select method |
| Attention | Equal attention to all information | Quickly identify what matters and what's noise |
| Failure handling | Confused, retry same approach | Diagnose root cause, switch strategy |
| Resource judgment | Can't distinguish good from bad sources | Quickly assess authority, relevance, currency |

### Implication for this skill

The skill should teach users to organize knowledge like experts:
- Group concepts by mechanism, not by name
- Classify problems by type before solving
- Develop judgment about what matters
- Build failure models (when and why things break)

## Cognitive Apprenticeship Framework

Expert knowledge is largely tacit — experts can't always articulate how they make judgments. Cognitive apprenticeship makes this tacit knowledge visible through four moves:

### 1. Modeling
Show how an expert would approach this topic:
- "Here's how I'd structure my understanding of X..."
- "An expert entering this field would first look at..."
- "The key question an expert asks is..."

### 2. Coaching
Point out where the learner's understanding might be off:
- "Beginners often confuse X with Y because..."
- "A common trap here is thinking that..."
- "If you find yourself doing X, you've probably missed..."

### 3. Scaffolding
Provide structured support that enables practice:
- Concept maps with blanks to fill
- Analysis frameworks to apply to examples
- Decision trees for common choices
- Checklists for evaluating work quality

### 4. Fading
Gradually reduce support as competence grows:
- Stage 1: Full framework provided, learner fills in details
- Stage 2: Partial framework, learner extends it
- Stage 3: Learner builds own framework, mentor validates
- Stage 4: Learner evaluates others' frameworks

## Deliberate Practice Principles

Learning requires practice with feedback, not just reading. Effective practice has these properties:

1. **Targeted**: Focuses on a specific sub-skill, not everything at once
2. **Challenging**: Just beyond current ability (not too easy, not impossible)
3. **Feedback-rich**: The learner can tell if they got it right
4. **Repeatable**: Can be done multiple times with variation

### Applying to topic learning

| Learning stage | Practice type | Feedback mechanism |
|----------------|---------------|-------------------|
| Concept building | Explain in own words, draw relationships | Compare to expert explanation |
| Method learning | Apply method to a known case | Compare output to known answer |
| Judgment building | Evaluate a real example | Compare evaluation to expert assessment |
| Design/research | Create something new | Peer/mentor review against criteria |

## Cognitive Load Management

Don't overwhelm the learner. Key principles:

1. **One thing at a time**: Each stage should have one primary learning objective
2. **Build on prior knowledge**: Connect new concepts to what's already understood
3. **Worked examples first**: Show complete solutions before asking learner to solve
4. **Reduce extraneous load**: Don't make the learner figure out what to read or in what order — that's the skill's job
5. **Increase complexity gradually**: Simple cases → typical cases → edge cases → adversarial cases

## Transfer Strategies

For learners coming from adjacent fields, explicitly map:
- "In your field, X is called Y"
- "This is similar to Z that you know, except..."
- "The key difference from your background is..."
- "Your intuition about X will serve you well here, but be careful about Y"
